<topic id="scope-research-and-risk" wp="WP-0319" version="v1">

Operator: fix all subscriptions and download mechanics; always best quality; MKV with available original-language and English subtitles; produce a regular core installer, excluding offline packaging. Preserve all lists/history/media. Canonical evidence: 3,102 failed recurring video attempts since Sep 19 across 21 subscriptions (3,099 reject the producer-generated exact dot path template); two singles finalized at 360x640 although current identical-engine metadata resolves 1080x1920.

Spec anchors: PRODUCT_SPEC.md default archive/output media policy and recurring acquisition; TECHNICAL_DESIGN.md managed-video and job runtime boundaries. Reuse existing runner, retry lineage, publication guards, stream validation, typed agent operations, bounded activity and installer entrypoint.

Research basis: yt-dlp README format-selection/subtitle/plugin documentation and current YoutubeDL.py / extractor/youtube/_video.py (https://github.com/yt-dlp/yt-dlp). Structured pre/post metadata supports verifying selected formats. Pre-process plugins run after initial subtitle selection, so the product plugin must recalculate requested_subtitles using process_subtitles; original automatic tracks have -orig keys and language is carried by original audio formats. Use an app-owned embedded plugin in attempt staging, not changes to the attested dependency/provider tree. Choose best container-neutral video/audio, original audio preference, dynamic original-language and English captions (authored first, automatic/translated English when available), then lossless MKV mux and independent ffprobe validation. Do not fetch every machine translation; do not use fixed Japanese/Korean language assumptions, a fixed 1080p ceiling, repeated metadata extraction, or silent quality fallback.

Red team/controls: exact dot means no extra grouping, not traversal; reject parent/root paths unchanged. Legacy queued choices cannot defeat current archive policy. Missing policy plugin receipt or progressive-only YouTube fallback must not publish a low-quality success. Truly low-resolution sources with complete format discovery remain valid and labeled. Captions missing at source are explicit; available selected subtitles missing in output fail. Original/manual/automatic translation labels and language tags remain truthful. Recovery works on the full canonical eligible set, preserves original-to-replacement lineage and ignores already-replaced attempts; no database writes outside the shared runtime. Back up production state before recovery. Never interrupt operator-owned processes without the required exact PID acknowledgement.

Validation: focused producer-to-consumer path tests, quality/subtitle plugin against real yt-dlp and independent ffprobe (including non-Japanese/Korean originals, unavailable subtitles, low-format/missing-receipt negative cases); full canonical recovery selection proof; governed core-only build retaining assigned 0.1.204 and unchanged changelog; hidden packaged semantic/manual/activity snapshots. Verify actual network subscription case through the product runtime before claiming downloads repaired. Installer installation/live recovery requiring replacement of an operator-owned process must await the exact PID acknowledgement after the reviewable build exists.

Packaged canary found a publication blocker: verified 1080x1920/60fps MKV retained in a staging path longer than 260 characters; raw MoveFileExW returned error 3. Microsoft documents extended-length Win32 paths (https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation). Resolve the existing staging file and destination parent with Rust canonicalize before the native call, which supplies extended-length Windows paths; retain no-replace flags. Reject shortening operator destinations, changing machine registry policy, or replacing atomic publication with copy/overwrite. Validate with a failing-then-passing long-path publication test, existing concurrent no-replace test, and exact packaged subscription retry.

Production recovery prerequisite: the operator's app is closed, and isolated headless mode deliberately refuses production data. Add an explicit --agent-background launch mode using the same Win32 quiet-window mechanism while retaining normal production startup and bridge permissions. Never relax headless isolation or fabricate proof against a copy. Reject combined headless/background flags. Microsoft ShowWindow documentation (https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow) specifies nonactivation for SW_SHOWMINNOACTIVE. Use ShowWindowAsync(SW_SHOWMINNOACTIVE) for production so the operator can restore it from the taskbar without a second instance; headless retains SW_HIDE. Verify minimized non-foreground state, production data-root identity, live bridge actions and real queue progress. The built-in manual must distinguish production background operation from disposable headless verification.

Live recovery exposed a provider lifecycle race: full-byte verification clears its prior attestation while status polling compares the incomplete identity and drops the live helper; launch checks also misread the in-flight state as corruption. Reuse the existing lifecycle mutex for the final launch-status read, and keep passive status polling non-destructive for living children. Actual verification failures still terminate the helper in the existing execution gate. Rust Mutex documentation (https://doc.rust-lang.org/std/sync/struct.Mutex.html) supports serializing readers with the existing writer; do not add stale trust or skip byte verification. Validate concurrent publication/waiting and existing tamper rejection, then observe the installed helper across concurrent jobs.

Recovery SQL measured 541 ms scanning job history versus 28 ms with the existing batch index and identical counts in one read snapshot. SQLite INDEXED BY (https://www.sqlite.org/lang_indexedby.html) is a required plan constraint, not a hint; the schema already guarantees idx_job_batch_created before runners. Bind the hot rollup query to that index, retain the serialized transaction, and test rollup correctness/concurrency. No live schema changes or maintenance operation is needed.

Production downloads reached the existing six-hour local cooldown after corroborated HTTP 429 subtitle responses. RFC 6585 section 4 (https://www.rfc-editor.org/rfc/rfc6585.html#section-4) establishes rate limiting and optional Retry-After; it does not mandate six hours. The current stored six-hour time is the app's own constant, not a captured server header. Add an explicit controlled-probe action that advances only the current download cooldown's next probe, retaining cooldown mode, existing exclusive canary lease, all request pacing, quality validation, and history. A product-selected five-minute minimum after latest evidence prevents immediate repeated retries; the action does not clear authentication/integrity holds or automatically reset later failures. Reuse the existing canary scheduler and outcome-driven recovery. Validate fresh/mature cooldown, hold rejection, unchanged history and exclusive lease; expose the same action in Options, typed agent command and manual.

The controlled real-video attempt isolated the remaining failure to English automatic translation (HTTP 429), with the provider alive and verified. yt-dlp maintainer guidance explicitly distinguishes translated captions from original/manual captions and documents --sleep-subtitles 60 (https://github.com/yt-dlp/yt-dlp/issues/13831#issuecomment-3712613129). Set the supported sleep_interval_subtitles parameter to at least 60 only when a YouTube selection includes translated captions. Do not discard English or relax final track validation. The same attempt exposed unconditional anonymous retry after any browser-authenticated error; its secondary sign-in failure incorrectly classifies the original subtitle error as rejected authentication. Preserve the explicitly selected session and first error instead of silently stripping cookies. Validate the exact failed English subtitle URL with a fresh extraction plus targeted delay; test translated/original/manual policy branches and preserve original error classification.
